# WEEK ONE NOTES

## What is an LLM?

LLM stands for **Large Language Model**.
It's an AI system trained on huge amounts of text so that it can understand and generate human-like language.
Examples include ChatGPT, Google Gemini, and Claude.

Imagine asking an AI:
Explain JavaScript in simple words.
The AI processes your message and generates an answer one piece at a time.

You enter a prompt
"What is JavaScript?"
        ⬇️
LLM processes the prompt
Uses learned patterns to predict what comes next
        ⬇️
AI generates a response
"JavaScript is a programming language..."


### How does an LLM learn?
Think about how you learn programming. You study examples of code, practise writing programs, and recognise patterns.
An LLM is trained on very large datasets. During training, it learns statistical patterns in language, code, and other data. It then uses those learned patterns to generate responses.
For example:
- Input: The sun rises in the ___
- Likely next word: east
The model learns patterns like this on a much larger scale. Real LLMs use complex neural networks, not just a simple list of words.

### Important terms
Term	Easy meaning
AI	The broad field of making machines perform intelligent tasks
LLM	An AI model specialised in processing and generating language
Training	The process through which a model learns patterns from data
Prompt	The instructions or question you give the AI
Response	The content the AI generates
Inference	Using an already-trained model to generate an answer
**Remember: Training is learning; inference is using what was learned.**

## What are tokens and tokenization?

### 1. What is a token?
A token is a small piece of text that an AI model processes.
A token can be:
- A whole word.
- Part of a word.
- Punctuation.
- A number or a piece of a number.
- Whitespace or other text-related content, depending on the tokenizer.

For example, the word apple might be one token for a particular tokenizer, while a longer or less common word might be split into multiple tokens.
Consider this sentence: I love programming!
A tokenizer might split it into pieces resembling:
**I** **love** **programming** **!**

### 2. What is tokenization?
Tokenization is the process of splitting text into tokens that a model can process.
The basic flow is:

Text: Hello world!
        ⬇️
Tokenizer splits the text
        ⬇️
Token pieces and their numeric IDs
        ⬇️
The model processes those IDs

A model doesn't simply receive your sentence as ordinary text internally. The tokenizer converts the text into token IDs — numbers representing token pieces in its vocabulary.

## What is inference?

Inference means running a trained AI model to get an output.
Suppose you create a chatbot for your website.
1. A user types: Write a JavaScript function to add two numbers.
2. Your application sends that prompt to an AI model.
3. The model processes the input and generates code.
4. Your application displays the generated code to the user.
That entire process of getting a prediction or response from the trained model is inference.

**Training vs inference**

Training = learning
The model learns patterns from data. This usually requires substantial computing resources and is done before you use the trained model.

Inference = answering
You give the trained model a prompt, and it generates a response. This is what happens when you chat with an AI.

## Parameters, context window, temperature and hallucination.

### 1. What are model parameters?
Model parameters are numerical values learned during training. They help determine how the model processes information and generates responses.
Think of them as the model's learned internal settings.

For example, an LLM with billions of parameters has billions of learned numerical values. These are not the same as settings you change when calling an API.
You may see model names describing sizes such as 7B or 70B. The B means billion parameters.
- A 7B model has approximately 7 billion parameters.
- A 70B model has approximately 70 billion parameters.
More parameters don't automatically mean a model is better at every task. Architecture, training data, training methods and other factors also matter.


### 2. What is a context window?
The context window is the amount of tokenised information a model can handle in a request, including relevant conversation history and instructions.
Imagine you're talking to an AI about your college project.
- You explain your project.
- You share your code.
- You ask follow-up questions.
- You provide error messages.
The model needs room to process that information.

#### Example of a context window:
Previous messages
Your project requirements and earlier questions
Current message
Your latest prompt and code
Model output
The response generated by the model
These all use tokens; the exact accounting depends on the model and API.

If the context window is exceeded, the application may need to shorten or remove older content, or the API may reject the request.
A larger context window allows more information to fit into a request, but it doesn't guarantee that the model will understand every detail perfectly.


### 3. What is temperature?
Temperature is a setting that influences how a model selects its next token.
In simple words, it affects how predictable or varied the generated response tends to be.

**Low temperature**
More predictable
Useful when you want consistent, focused answers.
Prompt: What is 2 + 2?
Likely response: 4

**Higher temperature**
More varied
Can be useful for brainstorming and creative writing.
Prompt: Give me an unusual name for an AI startup.
Possible response: NeuralNest

A higher temperature doesn't mean the model becomes more intelligent, and a lower temperature doesn't guarantee correctness. The effect also depends on the model and provider.


### 4. What is a hallucination?
An AI hallucination occurs when a model produces information that is false, fabricated or unsupported, sometimes while sounding very confident.
For example, imagine asking:
Who invented a programming language that doesn't exist?
The AI might invent a person's name and a date rather than admitting it doesn't know.

Other examples include:
- Inventing a library function that doesn't exist.
- Giving a fake research paper or source.
- Making up facts about a company.
- Producing code that looks correct but doesn't work.

How can developers reduce hallucinations?
- Give the model clear instructions.
- Supply relevant and reliable information in the prompt.
- Ask it to acknowledge uncertainty.
- Verify important facts and test generated code.
- Use retrieval from trusted documents when the application requires it.
You cannot guarantee zero hallucinations simply by lowering temperature.

**Concept Remember it as**
Parameters = Learned numerical values inside a model
Context window = How much tokenised information fits in a request
Temperature = Influences the variety of generated responses
Hallucination = An answer that sounds convincing but is false or unsupported

# Git and GitHub

## 1. What is Git?
Git is a version control system. It tracks changes to your code over time.
Imagine you have a React project. You make changes to your homepage, then change your backend, and suddenly everything breaks.
Without Git, you might struggle to recover your earlier working code.
With Git, you can save snapshots of your project and inspect or restore earlier versions.
Think of Git as a save system for your code.

## 2. What is GitHub?
GitHub is an online platform where you can store Git repositories, share code and collaborate with other developers.

**Git**
The tool on your computer that tracks changes.

**GitHub**
A website where you can host repositories and collaborate with others.

**Git and GitHub work together, but they are not the same thing.**

## 3. What is a repository?
A repository, often called a repo, is a project tracked by Git.

It could contain files such as:
project1-learning/
├── week1-notes.md
├── experiment.py
└── README.md

## **Git & Github workflow**

1. Initializing and Setting Up

• git init
	• Creates a brand new, empty local Git repository in your current project folder.
• git config --global user.name "Your Name"
	• Sets the display name that attaches to your saved snapshots.
• git config --global user.email "you@example.com"
	• Links your email address to your commits so GitHub recognizes you.

2. Checking Status and Staging

• git status
	• Shows the current state of your folder, highlighting untracked, modified, or staged files.
• git add .
	• Stages all new and changed files, preparing them to be saved in the next snapshot.

3. Saving and History

• git commit -m "Your descriptive message"
	• Saves your staged snapshot permanently to your local computer's history.
• git log
	• Lists the timeline of past commits so you can see your project's history.

4. Connecting to the Cloud (GitHub)

• git remote add origin <URL>
	• Links your local computer project to an empty, remote repository on GitHub.
• git remote -v
	• Verifies the connection link by displaying the current remote URLs.

5. Branching and Experimenting

• git switch -c feature/my-new-idea
	• Creates and jumps into a new sandbox branch, separating your experiments from the stable code.
• git branch
	• Lists all existing branches in your project and highlights the one you are currently using.

6. Sharing and Proposing Changes

• git push -u origin feature/my-new-idea
	• Uploads your local branch and commits to GitHub for the first time.
• Pull Request (PR)
	• A digital proposal created on GitHub's website asking to merge your experimental branch into the stable main branch.

7. Integrating the Work

• git fetch
	• Downloads the latest updates and branches from GitHub without changing your local files.
• git merge feature/my-new-idea
	• Combines the history and files of your experimental branch directly into your current branch.
